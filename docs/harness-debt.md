# Harness debt

Known debt in the checks, in delivery, and in the harness agents work in. The code's debt is in
[`tech-debt.md`](tech-debt.md), which says what a row holds, what each Size means, and when to add
or remove one. The weekly maintenance report counts both files' rows together.

## Checks

| Debt | Why it matters | Issue | Size |
| --- | --- | --- | --- |
| Of the checks a merge can wait for, only `Quality Gate` is required on `staging` and `main`, and the merge queue isn't on. Every workflow that checks a pull request starts on each one and on `merge_group`, and ends in one job to require ([`ci.md`](agents/ci.md)). | A red check other than `Quality Gate` doesn't stop a merge, nothing tests the tree that lands, and the git hooks can be skipped. What's left is an admin's: require those jobs on both branches, and turn the merge queue on. | No issue yet | medium |
| The review, `@claude` and gardening jobs run on `claude-sonnet-5-5` ([`ci-agents.md`](agents/ci-agents.md)). SERP's Token Budget keeps judgment work, review included, on the strongest model. | A weaker reviewer misses more, and each miss is a merged bug or another round. Which model the token's plan pays for is the owner's decision. | No issue yet | medium |
| The review says how many of a pull request's changed files it read, and the count is its own. The review's guard can hold the total to the pull request, but it can't tell a file read from a file skimmed ([`ci-agents.md`](agents/ci-agents.md), Code review). | A thin review can still pass by overstating what it read, and the run's transcript is the only record. | No issue yet | medium |
| TD-11: Every browser spec shares one database and one set of seeded users, and one local workerd process renders every page and prefetch, so the browser tests run on one Playwright worker (`playwright.config.ts`). | In parallel, specs interfere (publishing moves sitemap dates) and navigations pass the 5-second expect timeout. Run one at a time, the whole suite takes 11 to 14 minutes in CI, about ten minutes more on every pull request, and about half an hour locally. Each spec's own users and data, or D1 state per worker, and a preview per worker would let it run in parallel. | No issue yet | large |
| TD-12: No code formatter. | Formatting is left to each author and to review. Deferred on purpose: a reformat of the whole repository buries real changes, so it comes in a pull request of its own that formats once and lists that commit in `.git-blame-ignore-revs`. | No issue yet | medium |
| Whether a new or changed D1 query is bounded and backed by an index is held by hand: `pnpm run d1:profile` before merging ([`d1-cost.md`](agents/d1-cost.md)). The rows-read budgets cover only the hot requests. | Rows scanned grow unseen until the bill does. | No issue yet | medium |
| The API logger refuses personal data only by field name (`ip`, `email`, `password`, `token`, `authorization`, `cookie`), and ESLint only refuses `console` in `functions/` ([`code.md`](agents/code.md), Logging). | Personal data under another field name, or inside a message, reaches Workers Logs. | No issue yet | medium |
| The vocabulary lint refuses only Team, Workspace and the Template Library's old names in UI copy ([`code.md`](agents/code.md), Vocabulary). | Other product terms drift in copy unnoticed. | No issue yet | small |
| Tests are named for the behavior they check by judgment alone. | A test named for its code hides what broke when it fails. | No issue yet | small |
| The type-aware lint runs by area and leaves the root config files out (`scripts/lib/lint-runs.ts`). | An `any` or an unsafe cast passes in `next.config.ts` and the other root configs. | No issue yet | small |
| The duplicate check (jscpd) doesn't read the skills' scripts under `.claude/skills/` or the actions' scripts under `.github/actions/`. | A clone there passes. | No issue yet | small |
| The weekly report tells the review's findings by their author: top-level inline comments by `github-actions[bot]` or `claude[bot]` ([`ci-agents.md`](agents/ci-agents.md)). | Another workflow commenting inline with the job's token would count as review findings. | No issue yet | small |
| The ask rules in `.claude/settings.json` name the command groups of Wrangler 4.143, and nothing fails when a later Wrangler adds one ([`agent-tooling.md`](agents/agent-tooling.md)). | A new command that changes the Cloudflare account would run without asking. | No issue yet | medium |
| Ten product behaviors have no automated check, each marked "No automated check yet" in its product doc: auth cookies being `httpOnly` with no token kept in the browser; non-managers seeing an Organization's avatar without its controls; Share replacing a run's link; the 5-Template import limit; the import preview's guardrails; publisher ownership for library imports; the API copying only public Templates; the confirmation before "Load latest version"; Required tools links never rewritten; and the missing Reopen action ([`docs/product/`](product/index.md)). | A behavior no test proves can change unnoticed; the weekly report counts them. | No issue yet | medium |
| Two stand-in GitHub APIs serve the workflow tests: `tests/support/githubApiStandIn.ts` and the one in `tests/support/workflowGuards.ts`. | They can drift apart, and a guard tested against one may fail against the other. | No issue yet | small |

## Delivery

| Debt | Why it matters | Issue | Size |
| --- | --- | --- | --- |
| Staging answers anyone, with `noindex` on every response. SERP's [Staging Access](https://github.com/serpcompany/serp/blob/main/docs/engineering/standards/staging-access.md) standard puts each Staging behind an HTTP Basic gate in the Worker, but Run Keys send `Authorization: Bearer` to `/api/mcp`, so a gate needs the key moved off that header or `/api/mcp` left out of it. | Anyone can browse Staging and what it holds. The owner decides: build the gate and choose how Run Keys pass it, or record the exception in `AGENTS.md`. | No issue yet | medium |
| Staging takes anyone's sign-up, with email verification off (`AUTH_EMAIL_VERIFICATION_REQUIRED = "false"` in `wrangler.toml`) and no allowlist; SERP's Better Auth standard limits who may sign up on Staging. | Anyone can make an account on Staging and use it. Staging's accounts are disposable, so this is the owner's decision: an allowlist, or the exception written into `AGENTS.md`. | No issue yet | medium |
| GitHub closes an issue from a pull request only when it targets the default branch, which is `main` while work merges into `staging` ([ADR 0002](adr/0002-keep-staging-and-main-and-promote-by-squash-merge.md)). `Closes #N` in a pull request into `staging` closes nothing. | Finished work leaves its issue open until someone closes it by hand or a promotion names it, so the open issues overstate what's left. Making `staging` the default branch is the owner's call, with Devin. | No issue yet | medium |
| `wrangler.toml`'s top level, which SERP's Environment Configuration keeps for local runs, binds Production's D1 database (`serp-checklists-db`) and upload bucket, and the production scripts reach Production through it (`db:migrate:d1:prod`, `db:migrations:check:prod`, `check:prod:d1-schema`, `db:seed:official:remote`). | A local command that adds `--remote` without naming an environment acts on Production. Moving the production scripts to `--env production` and pointing the top level at local resources ends that, a change to every remote script and its permission rule. | No issue yet | medium |
| Production's upload bucket, `serp-checklists-uploads`, which Staging shared until it got `serp-checklists-staging-uploads`, reported 0 objects on 2026-10-12 (`wrangler r2 bucket info`, whose count can lag). | If Staging's uploads are in it, Staging rows name files its own bucket lacks. Confirm the count once the metrics settle, and delete this row if it is still 0. | No issue yet | small |
| CI deploys with the Cloudflare global API key (`CLOUDFLARE_API_KEY` and `CLOUDFLARE_EMAIL`), not a token scoped to what the deploys touch ([`ci-deploys.md`](agents/ci-deploys.md)). | A leaked key can act on everything the account can. A token scoped to the account's Workers, D1 and R2 limits that; making one, and replacing the secrets, is the owner's. | No issue yet | medium |
| The review authenticates with Claude's app, whose workflow validation skips the action while `code-review.yml` on the pull request's base differs from `main`'s: every pull request into `staging` went unreviewed from #260 to #296, 34 of them ([`ci-agents.md`](agents/ci-agents.md)). Now that Claude posts nothing itself, passing the job's own token as `github_token` might remove the skip; it is untested. | A change to the review workflow turns the review off for every pull request into `staging` until a promotion. | No issue yet | medium |
| No admin is named to keep `CLAUDE_CODE_OAUTH_TOKEN`, the token every Claude job uses ([`ci-agents.md`](agents/ci-agents.md)). | When it expires or its owner's plan changes, every review, `@claude` request and gardening run fails until someone notices. | No issue yet | medium |
| Which tags the Google Tag Manager container runs on Production is set in Google's interface, not in the repository ([`privacy.md`](product/privacy.md)). | A tag from an origin the security headers already allow could collect data with no pull request and no change to the privacy doc. The owner keeps the container. | No issue yet | medium |

## Harness

| Debt | Why it matters | Issue | Size |
| --- | --- | --- | --- |
| Remote D1 and R2 commands run through the Wrangler login of whoever runs the session ([`database-operations.md`](agents/database-operations.md)), so an agent session can use a login that reaches the whole Cloudflare account. | An agent session holds credentials that can change Production, held back only by permission rules. A read-only token for agents, with writes left to the owner or CI, would limit it; setting that up is the owner's. | No issue yet | medium |
| `verify-web`'s recordings need ffmpeg on the PATH, the Chrome DevTools server needs Chrome, and the billing flows need the Stripe CLI. All three are installed per user; `.mcp.json` pins only the Chrome DevTools server. | Cloud agents and teammates' agents may lack them, or run other versions, and a check that needs one fails or is skipped. | No issue yet | medium |
| Docs over the 300-line budget each have an allowance at their size, which only shrinks: on 2026-10-12, 18 docs, led by `docs/agents/ui-screen-inventory.md` at 2,699 lines and `docs/agents/frontend.md` at 719. | An agent loads a whole doc to answer one question. Each has to be split by topic, a pull request at a time. | No issue yet | large |
| Querying the deployed Workers' logs ([`observability.md`](agents/observability.md)) needs a read-only Cloudflare API token, which only an owner can make. | Until then an agent can't read why Staging or Production failed. | No issue yet | medium |
| Errors the browser reports reach Workers Logs with the production bundle's minified stack, since no source maps are kept to read it ([`observability.md`](agents/observability.md)). | A stack names bundle chunks and columns, not the source, so finding the failing code takes guesswork. | No issue yet | medium |
| Git Workflow's `brainstorm` label doesn't exist yet, and the labels in use that [`issue-tracker.md`](agents/issue-tracker.md) doesn't document wait to be documented, merged or deleted. | An issue with no acceptance criteria looks ready to agents, and an undocumented label means nothing to them. Changing the labels is an admin's. | No issue yet | medium |
| The stop hook checks the checkout the session itself works in. A subagent working in another worktree has the edit hook on each file it writes, and nothing at the end of its turn: a file it rewrote with a shell command, or a doc link it broke, waits for the git hooks. `SubagentStop` may cover it; whether its `cwd` is the subagent's worktree is untested. | A subagent's whole change is first checked when it commits. | No issue yet | medium |
| The branch-name form, which carries the issue number ([`issue-tracker.md`](agents/issue-tracker.md)), is held by prose alone. | Nothing fails a branch that breaks it, so it holds only while each agent reads the doc. A check on the branch name could join the pull request workflow. | No issue yet | small |
| `.housekeeping` lists the disposable paths by name, so scratch written straight into `tmp/` stays; a checkout's `tmp/` can hold hundreds of loose files beside `tmp/backups/`. | Disks fill, and emptying all of `tmp/` would take the D1 backups with it. | No issue yet | medium |
| `verify-web` and `verify-api` haven't been run end to end with their proof kept ([`verification.md`](agents/verification.md)). | A skill that hasn't run is a draft; its steps may not work as written. | No issue yet | small |
| `dev:all` starts its search for a free port at 3000 in every checkout (`scripts/dev-auto.ts`), not at the checkout's own `dev` port from `tools/checks/ports.mjs`. | A worktree's `dev:all` can take the port the main checkout's docs and skills name. | No issue yet | small |
