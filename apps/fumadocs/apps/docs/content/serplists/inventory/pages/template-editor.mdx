## Identity

- Current URLs:
  - `/dashboard/templates/new`
  - `/dashboard/templates/:id/edit`
- Future URLs: same route family unless editor IA changes
- Route pattern: create and edit routes sharing the same editor shell
- Page type/template: nested authoring workspace
- Primary entity: template definition
- Access: authenticated

## Purpose

- Audience: creators authoring reusable templates
- Goal: make nested template structure obvious and editable without confusion between source and run
- Primary CTA: save template
- Secondary CTA: add/remove sections and tasks, edit metadata and SEO, toggle public/private

## Route Pattern & Examples

- Example create route: `/dashboard/templates/new`
- Example edit route: `/dashboard/templates/123/edit`
- Shared editor shell across both routes

## Migration Notes

- Must preserve:
  - template vs run distinction stays explicit
  - metadata/SEO remain separate editing modes
  - nested authoring stays obvious at section -> item -> content block level
- Allowed to change:
  - panel layout, keyboard shortcuts, density, responsiveness
- Open questions:
  - which editor blocks become reusable UI-block records first

## Integration QA Checks

- Create and edit routes share the same authoring rules
- Existing template data hydrates correctly on edit route
- Save errors are visible at the right level
- Removing sections/tasks is explicit and recoverable enough
