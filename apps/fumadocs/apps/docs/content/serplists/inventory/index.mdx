Use this section to document each route as a rebuildable record.

Each page record should answer:

- what the route is for
- who it serves
- what content it contains
- what features and states it depends on
- what metadata and schema expectations must survive the redesign

The records here are intentionally CMS-agnostic and UI-agnostic.

## Record Standard

Every page record should include:

- identity
- purpose
- route pattern and examples
- metadata template
- schema.org template
- content inventory
- media inventory
- UI blocks and components
- feature list
- states
- integrations and analytics
- migration notes
- integration QA checks

Start new records from [Page Inventory Template](/docs/inventory/page-template).
