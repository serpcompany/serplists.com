## Purpose

- Make the template authoring model obvious enough that creators do not lose track of nested structure

## Trigger

- User creates or edits a template in the editor

## Inputs

- template metadata
- sections
- items/tasks
- content blocks
- SEO fields

## Outputs

- saved template source definition
- updated nested authoring state

## Rules & Validation

- template structure is `sections -> items -> contents -> subItems`
- metadata and SEO are separate editor modes from section and task editing
- double-click in the sidebar enables inline editing for sections and tasks
- section and task removal happens inline from the outline

## States

- Idle: current selection visible
- Loading: existing template load or save in progress
- Success: template saved or updated
- Error: validation or save failure

## Fallback

- If save fails, keep current editor state and show validation at the right level

## Dependencies

- template schemas
- editor forms
- save/load APIs
- upload and media support for content blocks

## Tracking Events

- save-template
- add-section

- remove-section
- remove-task
- publish-toggle

## Must Preserve

- source template editing never feels like run execution
- nested structure stays explicit and navigable

## Integration QA Checks

- Sidebar rename and selection still work
- Metadata and SEO modes remain separate
- Save failures do not silently discard work
