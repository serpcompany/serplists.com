## Purpose

- Let a private run be shared for guest-accessible execution without exposing the private workspace

## Trigger

- User creates a share link from the private run view

## Inputs

- private run identity
- share action from authenticated workspace

## Outputs

- share token
- guest route at `/share/:shareToken`

## Rules & Validation

- share creation happens only in the private run view
- shared route must stay guest-accessible
- shared route must hide private-only actions like title editing and re-sharing

## States

- Idle: no share action taken yet
- Loading: share link generation in progress
- Success: share token created and usable
- Error: share creation failed

## Fallback

- If share generation fails, the private run remains usable without exposing token state

## Dependencies

- share-token generation
- shared run fetch/update APIs

## Tracking Events

- share-link-create
- share-link-success
- share-link-failure
- shared-run-opened

## Must Preserve

- guest execution works without login
- shared view never exposes private workspace controls

## Integration QA Checks

- Private share action still produces a valid shared route
- Shared route is accessible without auth
- Shared route suppresses private-only controls
