## Purpose

- Apply entitlement rules consistently when an action requires a higher plan

## Trigger

- User attempts a gated template action
- User opens billing management from account

## Inputs

- current plan or entitlement status
- action being attempted
- auth state

## Outputs

- allowed action
- billing checkout redirect
- billing portal redirect
- visible gated state messaging

## Rules & Validation

- gating appears in public template copy/save flows
- gating appears in console template copy/save flows
- account billing controls must reflect current billing availability and state

## States

- Idle: ungated or not yet checked
- Loading: billing or entitlement query pending
- Success: action allowed or billing flow launched
- Error: billing unavailable or entitlement lookup failed

## Fallback

- If billing status cannot be loaded, keep the user informed and avoid ambiguous CTAs

## Dependencies

- entitlement state
- billing checkout
- billing portal
- account billing status query

## Tracking Events

- gated-action-attempt
- checkout-redirect
- billing-portal-open
- billing-unavailable

- template action row

## Must Preserve

- public and console gating rules stay aligned
- account billing state remains explicit when unavailable or loading

## Integration QA Checks

- Gated actions route into billing only when required
- Non-gated actions do not incur billing checks unnecessarily
- Account billing panel clearly reflects success, cancel, and unavailable states
