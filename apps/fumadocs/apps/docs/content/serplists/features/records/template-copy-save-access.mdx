## Purpose

- Let users add a reusable template to their workspace from public or console detail surfaces
- Keep entitlement rules consistent wherever the action appears

## Trigger

- User clicks copy or save on a template detail surface

## Inputs

- auth state
- entitlement or plan state
- template identity
- return path for auth handoff when needed

## Outputs

- copied template in workspace
- auth redirect
- billing redirect
- visible success or failure outcome

## Rules & Validation

- Signed-out users must log in before copy/save completes
- Return path should preserve the requested destination
- Non-Pro users can be routed into billing checkout for gated copy/save actions
- Console and public detail flows must stay aligned

## States

- Idle: CTA visible
- Loading: copying or entitlement check in progress
- Success: copied template available in workspace
- Error: copy failed or entitlement check failed

## Fallback

- If copy fails, keep the user on the current detail page
- If auth is missing, redirect to login with destination preserved

## Dependencies

- auth state
- template copy/save API
- billing checkout path

## Tracking Events

- copy-start
- copy-success
- copy-failure
- auth-redirect
- billing-redirect

- template action row
- billing or auth CTA state

## Must Preserve

- the same rules apply on every copy/save surface
- users do not lose context when auth is required

## Integration QA Checks

- Signed-out copy/save redirects to login with the correct return path
- Gated copy/save can redirect into billing
- Success path leaves the copied template in the workspace
