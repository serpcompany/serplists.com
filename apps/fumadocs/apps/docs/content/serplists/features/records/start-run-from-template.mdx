## Purpose

- Convert a reusable template into an execution copy
- Preserve a consistent handoff into run execution regardless of entry point

## Trigger

- User clicks start run from a template surface

## Inputs

- template identity
- optional run name
- auth state when required by the entry surface

## Outputs

- created checklist run
- redirect to `/dashboard/runs/:id`

## Rules & Validation

- run creation can appear in multiple places
- successful creation always ends in the private run route
- detail surfaces may ask for a run name before creation

## States

- Idle: start-run CTA visible
- Loading: run creation in progress
- Success: run created and navigation occurs
- Error: run creation fails with recovery path

## Fallback

- If run creation fails, keep the user on the source page and preserve entered name if possible

## Dependencies

- run-creation API
- template identity and normalized content
- navigation into run route

## Tracking Events

- start-run click
- run-name submitted
- run-created
- run-create-failure

## Must Preserve

- every successful entry point lands in the run route
- entry-point differences do not change the resulting run behavior

## Integration QA Checks

- All start-run entry points produce the same run destination pattern
- Run naming flow behaves consistently across surfaces
- Failure leaves the user in a recoverable state
