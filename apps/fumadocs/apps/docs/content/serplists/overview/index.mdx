This docs app is the working inventory for the Serplists UI integration effort.

It exists to define the product as:

- content
- structure
- behavior
- reusable UI expectations

It should not mirror the current implementation details or preserve the current frontend composition.

## What Goes Here

- `Inventory`: one record per route or route family
- `Features`: one record per reusable behavior
- `UI Blocks`: reusable block and component expectations once the new UI docs exist
- `Glossary`: stable domain terms used across the audit

## Working Rule

Document what the new UI must preserve, not how the current UI happens to render it.

Good examples:

- semantic sections
- route patterns
- states and edge cases
- feature rules and validation
- metadata and schema expectations

Avoid:

- screenshots as source of truth
- CSS classes
- raw HTML
- implementation-only component details

## Recommended Workflow

1. Start with the [page inventory template](/docs/inventory/page-template).
2. Seed route records from the 2026-04-09 audit.
3. Extract reusable behavior into [feature records](/docs/features/feature-template).
4. Link any repeated shell or content patterns into [UI block records](/docs/ui-blocks/ui-block-template).
5. Use the seeded records as the checklist during redesigned UI integration.

## Current Seed Scope

The first pass includes:

- key page records for discovery, detail, editor, execution, and account surfaces
- feature records for copy/save, start run, run execution, sharing, editor authoring, and billing gating
- a placeholder UI block template for later component inventory work

## Success Criteria

- every important route has a rebuildable record
- every important behavior has a reusable feature record
- private vs public expectations are explicit
- integration QA can walk these docs as a checklist
